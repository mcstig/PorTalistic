## What's new in 0.7.0.7

**Steam's interface runs on your Mac's GPU**
- Steam's own screens (Big Picture, the store, your library) were drawn by the Linux system's processor. On a MacBook Pro with an M1 chip and 8 GB, that used most of the processor and Big Picture was laggy and choppy. Now Portalistic tries your Mac's GPU the first time Steam starts, checks that it works, and goes back to the processor by itself if it doesn't (a banner tells you). The first tries inside Steam usually fail before one works, so the screen can blink for up to a minute or two the first time.
- Copies that are already set up try it once after the update, when Steam has been open for a few minutes and nothing is downloading or running. Steam restarts once.
- **Bottle > Steam's Interface: GPU or Processor…** lets you choose by hand. A choice you make is kept.

**Games you install while Steam is open now start**
- If a game has a Linux version, Steam installed that one when you installed the game with Steam already open, and the Linux version can't run here: you pressed Play, nothing happened and the button came back. Portalistic now notices, and restarts Steam once by itself (never while a game is running) so the game installs its Windows version and starts. A banner says why. Steam may download the game again. You can still keep a game on its Linux version with `bottle version GAME linux`.
- The first time a Windows game starts, it sets itself up for a few minutes (about 9 on a 2020 M1 MacBook Pro) without showing anything. A banner now says "Setting up <game> for the first time" so you know to wait.

**Fixed**
- The check behind `bottle steam-gpu on` gave up after about 20 seconds and put Steam back on the processor just before it would have worked. It now waits up to three minutes.

**Good to know**
- This release reuses the Linux image of 0.7.0, so there is no big download. Copies of 0.7.0.3 to 0.7.0.6 offer the update when they open.
